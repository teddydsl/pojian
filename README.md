# 破茧（Pojian）

网页端 3D 探索游戏工程。玩家扮演刺猬，探索手工针毡微缩风格的奇幻茧林，进入获得许可的树洞茧房，通过空间、颜色与声音感受不同的信息环境。

## 工程位置

项目根目录为黑客松工作区内的 `pojian/` 文件夹。后续游戏代码、美术资源、音频、配置、测试与本项目文档均存放在此目录内；黑客松目录根部的通用流程文件不属于游戏工程。

## 执行阶段

原始黑客松版本按阶段 0～4 制作并已上线。当前根据反馈增加阶段 4.1，再按 **5A 单人探索交互 → 5B 数据体验 → 5C 美术与世界扩充** 推进；阶段 6 才做真实玩家互访。建模和森林素材可并行制作，游戏内替换仍须经过对应阶段验收。

每一阶段均交付 `reviews/` 下的 HTML 验收页。只有用户在聊天中确认该阶段通过后，才开始下一阶段。

| 阶段 | 目标 | 完成标志 |
|---|---|---|
| 0. 定范围 | 锁定演示路线、房间主题与资源清单 | 明确一条完整体验路径和核心素材 |
| 1. 灰盒闭环 | 建项目和基础场景，完成移动、敲门、进入与返回 | 不依赖正式美术即可走通流程 |
| 2. 核心表现 | 接入刺猬、针毡森林、蘑菇、树洞、镜头与开门动画 | 主路径具有目标视觉与连贯转场 |
| 3. 内容接入 | 完成不同茧房主题、音效、资料面板及示例网页 | 房间可辨认，数据页可打开并返回 |
| 4. 验收优化 | 检查加载、帧率、碰撞、交互、链接与失败恢复 | 演示设备上连续走通两次 |
| 4.1 返回与镜头修复 | 修复外链返回、室内镜头与浏览器页标识 | 切回游戏即能继续探索 |
| 5A. 单人探索交互 | 地图、天气、数据入口、任务奖励、系统消息与设置 | 探索目标和反馈形成闭环 |
| 5B. 数据体验与交付 | 接入后续提供的数据链接、整理演示与发布 | 数据可浏览，返回可靠 |
| 5C. 美术与世界扩充 | 验收并接入并行制作的角色和森林素材 | 画风与性能共同达标 |
| 6. 真实互访 | 增加账号、屋主权限、申请、留言和消息 | 玩家之间可安全地申请并访问茧房 |

阶段 6 放在后续版本。详细模块、数据接入方式和验收标准见 [技术方案](docs/TECH_PLAN.md)。

## 目录约定

```text
pojian/
├─ README.md
├─ index.html            GitHub Pages 游戏入口（由 build:site 生成）
├─ docs/                  方案与后续设计文档

├─ scripts/               本地验收页构建脚本
├─ vendor/                带许可证的本地 Three.js 源码
└─ public/
   ├─ assets/
   │  ├─ models/          GLB 模型与动作
   │  ├─ textures/        针毡、苔藓等贴图
   │  └─ audio/           森林、房间与交互音频
   └─ data/               第一版示例内容配置
```

## 网页发布

`npm run build:site` 读取已验收的 5A.1 室内修订快照，生成根入口、5A 独立验收页、带内容哈希的脚本与无损 WebP 图标；本地 HTML 继续可直接打开。GitHub Pages 沿用 `main` 分支根目录，`.nojekyll` 保留。数据页基址与图标路径按根页面／验收页分别生成，适配 `/pojian/` 子路径。

原始归档和历史预览不在生产首页的加载链中；已验收模型精度不变。详细资源体积、性能估算与验证限制见 [5A.3 报告](docs/STAGE_5A_3_QA.md)。
