# 破茧（Pojian）

网页端 3D 探索游戏工程。玩家扮演刺猬，探索手工针毡微缩风格的奇幻茧林，进入获得许可的树洞茧房，通过空间、颜色与声音感受不同的信息环境。

## 工程位置

项目根目录为黑客松工作区内的 `pojian/` 文件夹。后续游戏代码、美术资源、音频、配置、测试与本项目文档均存放在此目录内；黑客松目录根部的通用流程文件不属于游戏工程。

## 执行阶段

第一版分 **6 个阶段**，第二版的真实玩家互访作为第 **7 个阶段**。阶段内可以交叉准备素材，但每阶段须达到验收点后再扩大功能范围。

每一阶段均交付 `reviews/` 下的 HTML 验收页。只有用户在聊天中确认该阶段通过后，才开始下一阶段。

| 阶段 | 目标 | 完成标志 |
|---|---|---|
| 0. 定范围 | 锁定演示路线、房间主题与资源清单 | 明确一条完整体验路径和核心素材 |
| 1. 灰盒闭环 | 建项目和基础场景，完成移动、敲门、进入与返回 | 不依赖正式美术即可走通流程 |
| 2. 核心表现 | 接入刺猬、针毡森林、蘑菇、树洞、镜头与开门动画 | 主路径具有目标视觉与连贯转场 |
| 3. 内容接入 | 完成不同茧房主题、音效、资料面板及示例网页 | 房间可辨认，数据页可打开并返回 |
| 4. 验收优化 | 检查加载、帧率、碰撞、交互、链接与失败恢复 | 演示设备上连续走通两次 |
| 5. 演示交付 | 固定版本、演示路线与备用方案 | 可重复运行的第一版 Demo |
| 6. 真实互访 | 增加账号、屋主权限、申请、留言和消息 | 玩家之间可安全地申请并访问茧房 |

若按现有 24 小时黑客松流程执行，阶段 0～5 对应首日 Demo；阶段 6 放在后续迭代。详细时间、模块、数据接入方式和验收标准见 [技术方案](docs/TECH_PLAN.md)。

## 目录约定

```text
pojian/
├─ README.md
├─ index.html            GitHub Pages 游戏入口（由 build:site 生成）
├─ docs/                  方案与后续设计文档
├─ reviews/               各阶段 HTML 验收页
├─ src/                   游戏与网页界面代码
├─ scripts/               本地验收页构建脚本
├─ vendor/                带许可证的本地 Three.js 源码
└─ public/
   ├─ assets/
   │  ├─ models/          GLB 模型与动作
   │  ├─ textures/        针毡、苔藓等贴图
   │  └─ audio/           森林、房间与交互音频
   └─ data/               第一版示例内容配置
```

当前状态：阶段 0～3 已获用户确认。美术方向采用用户选定的[上一版刺猬造型与新版茧内视角](reviews/art-style-gate.html)。[阶段 4 体验优化 HTML](reviews/stage-4.html)现已提交验收，调整与测试说明见[阶段 4 验收文档](docs/STAGE_4_QA.md)。阶段 5 须等阶段 4 获用户确认后再开始。正式标签与数据地址目前仍等待提供；阶段 4 的演示配置集中在 [`public/data/cocoons-stage4.js`](public/data/cocoons-stage4.js)。

阶段 1～4 验收页可直接从磁盘打开。Three.js r187 的本地源码保存在 `vendor/three/`，许可证随资源保存；`npm run build:review` 会从这些源码生成 `public/vendor/three.global.js`，使 HTML 无需远程 CDN 或开发服务器即可运行。正式项目的 Vite 构建配置将在后续阶段接入。

## 网页发布

`npm run build:site` 生成仓库根目录的 `index.html` 和本地 Three.js 浏览器脚本。根页面直接运行当前阶段 4 游戏；验收页仍保留在 `reviews/` 中。将独立仓库 `teddydsl/pojian` 的 `main` 分支根目录发布到 GitHub Pages 后，游戏地址为 `https://teddydsl.github.io/pojian/`，不会占用个人主页根路径。资源均使用相对路径，适配 `/pojian/` 子路径。
