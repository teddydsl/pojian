## 1. 产品与视觉基线

玩家扮演可做基础装扮的刺猬，从自己的树洞茧房出发，探索手工针毡微缩风格的奇幻森林，拜访内容各异的茧房。房间的布置、色彩、光线和声音表达屋主的信息环境。详细人物资料由室内面板引导至后续提供的网页数据页面。

- **角色**：圆润刺猬，刺、绒毛、围巾和小背包形成清晰轮廓。第一版只做颜色与一两件配饰切换，避免多套角色模型。
- **玩家资料**：开场选择少量自愿公开的个人与喜好标签；玩家先在自己的茧房看到这些标签，再走入森林。
- **世界**：苔藓地形、树根小路、树洞、树桩、木桥和针毡蘑菇；一个可步行探索的小型森林区域。
- **茧房**：外部沿用树洞与编织茧丝的共同语言，内部依据内容分别配置道具、主色、局部光照和环境声。人物标签仅用于寻找和识别，不直接决定房间风格。
- **入口反馈**：当前室外茧房使用模型原生开口，已移除重叠的旧门框与门扇；采用敲门、预设许可与转场进入。后续室内出口若增加门扇，与室外模型独立配置。
- **镜头**：森林使用略俯视的第三人称跟随镜头；进入茧房后，镜头必须置于完整穹顶**内部**，可以在室内环顾或跟随刺猬，不能把外部剖面概念图当作室内视角。数据面板位于侧墙，正前方保留出口；靠近面板时可以作短暂视角引导，点击后直接打开数据地址，返回游戏立即恢复可移动的室内视角。

## 2. 第一版技术架构

| 层 | 推荐方案 | 第一版职责 |
|---|---|---|
| 网页应用 | 现阶段原生 HTML/JavaScript；后续可迁移 Vite | 启动、资源路径、页面状态和构建部署；保持 GitHub Pages `/pojian/` 子路径可用 |
| 3D 渲染 | Three.js / WebGLRenderer | 森林、角色、茧房、灯光、镜头与过渡动画 |
| 美术资源 | 阶段 4.1 使用已确认的刺猬 GLB、环绕森林 GLB、蕨类 GLB 和优化后的毛毡茧房 GLB | 用户并行制作或提供更多场景组件；精修后再接入 |
| 2D 界面 | HTML/CSS 叠在 3D 画布上 | 地图、天气表盘、数据下拉、任务、消息、设置和交互提示；外部茧房名称仅作近距 HUD 提示，不放场景牌子或悬浮字 |
| 内容配置 | 当前为本地 JavaScript 配置 | 茧房 ID、公开标签、主题资源、音效、数据页链接 |
| 状态保存 | 浏览器本地存储 `pojian.save` version 2 | 5A.1 已迁移探索／面板偏好，保存访问次数与个人开关门；5A.2 接任务、收藏、徽章和消息生成；装扮与自选标签后续接入 |
| 音频 | 浏览器音频能力 | 森林底噪、各茧房环境声和敲门／开门反馈 |

采用 GLB 作为资源交付格式；当前本地验收页将优化后的模型嵌入脚本并用轻量解析器加载，保证 `file://` 可直接打开。重复森林模型共享网格与材质，蕨类地面使用 `InstancedMesh` 降低绘制次数。后续如加入角色待机、走路等动作，可改用 Three.js 的 GLTFLoader 和 AnimationMixer。参见 [Three.js 模型加载](https://threejs.org/manual/pages/loading-3d-models.html)、[AnimationMixer](https://threejs.org/docs/pages/AnimationMixer) 与 [InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)。

### 场景与模块

```text
App
├─ WorldScene：森林、路径、树洞入口、道具
├─ HedgehogController：输入、移动、朝向、动作
├─ CameraDirector：跟随、门口特写、室内、面板特写
├─ InteractionController：靠近、选中、敲门、进入、离开
├─ CocoonScene：房间主题、道具、光声配置
├─ AudioDirector：森林与房间声音的交叉淡入淡出
├─ DataPanelBridge：面板过渡、链接打开、返回恢复
└─ UI：标签、门牌、提示、操作与探索记录
```

第一版采用简单碰撞范围和明确路径，不引入完整物理系统。交互优先使用“接近后按键／点击”。现有蘑菇与植被为装饰；5A 计划另配置 8 个可采集点，只有带采集 ID 的对象参与任务，装饰蘑菇不会全部变成可采集物。

4.1 收尾采用 R2 锚点解耦：布局、导航边界、房门／面板／挂点与碰撞共用配置；移动按实际相机方向的地面投影计算。室内相机必须按完整压扁穹顶体积和角色净空解算，不能仅限制 XZ 半径。具体数值复核见[复核报告第 2 节](STAGE_5A_REVIEW_AND_ROADMAP.md#2-相机诊断的数值复核)。

### 状态流

```text
森林探索 → 茧房开口聚焦 → 敲门 → 预设许可 → 转场进入 → 室内探索
                                                    ↓
返回森林 ← 离开房间 ← 室内继续探索 ← 切回游戏 ← 数据页新标签
                                      ↑              ↑
                               面板点击后立即恢复游戏状态
```

第一版的示例茧房由内容预设许可状态；无需假装有实时玩家在线。关门茧房显示不可进入的原因。第二版才改为由屋主设置开关门、接收申请并决定许可。

## 3. 数据页面接入契约

第一版为每间茧房保留 `dataUrl` 配置。在真实地址提供前，使用项目内的示例数据页验证完整流程；示例内容须标明为演示数据。

```ts
type CocoonConfig = {
  id: string;
  name: string;
  ownerName?: string; // 由 layout 的稳定房间 ID 映射主人；显示名可改，id 不变
  themeId: string;
  themeTitle: string;
  accent: string;
  sound: string;
  personTags: string[];
  contentTags: string[];
  entrance: 'open' | 'closed';
  dataUrl?: string;
};
```

靠近侧墙信息面板后按 E 或点击互动按钮，直接打开配置的地址。新标签打开成功后，游戏页必须立即清除面板聚焦状态、恢复角色可见及移动；切回时不需要 Esc，也不再出现一次面板浏览中间阶段。浏览器拦截新标签或地址不可用时，提示重试或关闭，关闭后留在当前茧房且可继续移动。后续地址可优先采用同站点页面；只有确认目标页面允许嵌入时，才使用页内 iframe。目标站点可通过 `frame-ancestors` 等策略限制嵌入，见 [MDN 文档](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors)。

第二版如包含真实用户数据，进入许可与数据页面访问必须由服务端共同验证；游戏内的开门动画本身不能作为访问控制。

5A 浏览过列表只允许打开已拜访房间，链接接口显式传入 `roomId`，不能按当前场景推断目标。HUD 与室内面板共用房间配置，但分别恢复自己的原场景；在森林打开记录后返回，仍停在森林，不切换到室内机位。已发起外链打开仅表示导航成功，不等于已验证用户读完目标内容。

## 4. 针毡美术的网页实现原则

1. **先做造型，再做质感**：圆润的不规则轮廓、可见的绒团和手工接缝，比大量细丝更能在中远景被看见。
2. **近景必须有真实绒毛层次**：刺猬的腹部短绒、背刺和脸部边缘不能只用噪声贴图代替。密集细绒与成组背刺以实例化几何、毛束卡片或同等方案制作；颜色、粗糙度与法线纹理辅助表现纤维，远景再使用简化层级控制开销。身体与背刺要在同一轮廓上连续生长。
3. **道具做可复用组件**：针毡蘑菇至少有单只、成簇、高矮三种组合；通过尺寸、转角和位置变化丰富森林。
4. **房间有统一模板和可替换主题**：共用树洞入口、完整茧丝穹顶与基本碰撞空间，左侧保留柔光数据面板，正前方保留可走通的出口；替换道具组、蓝橙红局部光、环境声和面板视觉。参考图中的外部剖面仅用来判断材质，不作为室内镜头。
5. **把细节集中在近景**：重点打磨刺猬、蘑菇、门口和一间代表性茧房；远处森林使用简化模型、雾和背景层次。

用户提供的图片是美术参考，不是可直接放进场景的 3D 模型。第一版目标是抓住圆润轮廓、纤维质感和微缩摄影的光线层次，不以逐像素复现图片为验收标准。网页端先按桌面键鼠体验设计；触屏操作待目标设备明确后安排。需要在目标演示设备上测量加载、帧率和内存，再决定模型与贴图预算；不要仅凭单张效果图估算网页端性能。

## 6. 第一版完成标准

- 刺猬可在森林与室内流畅移动，镜头跟随稳定，靠近时主人家的名称清晰。
- 开场能选择基础装扮与公开标签，并在自己的茧房看到选择结果。
- 玩家能从自己的茧房出发，拜访至少一间获准进入的茧房并返回；未经许可不能进入。
- 至少一间茧房完整体现“内容决定空间、颜色、声音”的设计，其他示例房能明显区分。
- 数据面板点击后直接打开示例网页；返回后不丢失游戏位置，不要求再次按 Esc 才能移动。
- 在目标演示设备上完成实际测量与两次连续演示，不发生阻断主路径的加载或交互错误。

## 7. 第二版扩展

在第一版闭环稳定后加入账号与角色档案、真实玩家茧房、开关门、访问申请与留言、屋主授权、消息通知、服务端权限校验，以及更多森林区域。此阶段需要后端存储、身份认证和权限接口；不应把第一版的本地预设许可直接当成真实授权机制。
