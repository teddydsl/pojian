# 《破茧》技术方案与执行计划（v0.1）

> 目标：网页端 3D 探索游戏。第一版完成可重复演示的单人探索闭环；第二版加入真实玩家互访。阶段 1～3 已获用户确认；用户选定上一版刺猬和新版茧内视角，详见[美术基线](ART_STYLE_GATE.md)。[阶段 4 体验优化验收](STAGE_4_QA.md)进行中。本文记录总体架构和后续资源方向，当前实现边界以各阶段验收文档为准。

## 1. 产品与视觉基线

玩家扮演可做基础装扮的刺猬，从自己的树洞茧房出发，探索手工针毡微缩风格的奇幻森林，拜访内容各异的茧房。房间的布置、色彩、光线和声音表达屋主的信息环境。详细人物资料由室内面板引导至后续提供的网页数据页面。

- **角色**：圆润刺猬，刺、绒毛、围巾和小背包形成清晰轮廓。第一版只做颜色与一两件配饰切换，避免多套角色模型。
- **玩家资料**：开场选择少量自愿公开的个人与喜好标签；玩家先在自己的茧房看到这些标签，再走入森林。
- **世界**：苔藓地形、树根小路、树洞、树桩、木桥和针毡蘑菇；一个可步行探索的小型森林区域。
- **茧房**：外部沿用树洞与编织茧丝的共同语言，内部依据内容分别配置道具、主色、局部光照和环境声。人物标签仅用于寻找和识别，不直接决定房间风格。
- **开门动画**：先获准进入，再由树洞入口的茧丝向两侧展开；不能用动画暗示未经允许闯入。
- **镜头**：森林使用略俯视的第三人称跟随镜头；进入茧房后，镜头必须置于完整穹顶**内部**，可以在室内环顾或跟随刺猬，不能把外部剖面概念图当作室内视角；靠近中央数据面板时平滑切至正前方，再展开网页界面。

## 2. 第一版技术架构

| 层 | 推荐方案 | 第一版职责 |
|---|---|---|
| 网页应用 | TypeScript + Vite | 启动、资源路径、页面状态和构建部署 |
| 3D 渲染 | Three.js / WebGLRenderer | 森林、角色、茧房、灯光、镜头与过渡动画 |
| 美术资源 | Blender 制作，导出 GLB | 刺猬、树洞、蘑菇、地形组件、室内道具与角色动作 |
| 2D 界面 | HTML/CSS 叠在 3D 画布上 | 门牌、敲门、许可反馈、提示、标签、信息面板与返回按钮 |
| 内容配置 | 本地 JSON/TypeScript 数据 | 茧房 ID、公开标签、主题资源、音效、数据页链接 |
| 状态保存 | 浏览器本地存储 | 角色装扮、自选标签、已探索茧房和返回位置；第一版不依赖服务器 |
| 音频 | 浏览器音频能力 | 森林底噪、各茧房环境声和敲门／开门反馈 |

采用 GLB 作为资源交付格式，并通过 Three.js 的 GLTFLoader 加载；角色的待机、走路和进门等动作可由 AnimationMixer 播放。重复蘑菇、草团等静态道具可复用网格与材质，数量增加时采用 InstancedMesh。以上能力见 [Three.js 模型加载](https://threejs.org/manual/pages/loading-3d-models.html)、[AnimationMixer](https://threejs.org/docs/pages/AnimationMixer) 与 [InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)。

### 场景与模块

```text
App
├─ WorldScene：森林、路径、树洞入口、道具
├─ HedgehogController：输入、移动、朝向、动作
├─ CameraDirector：跟随、门口特写、室内、面板特写
├─ InteractionController：靠近、选中、敲门、进入、离开
├─ CocoonScene：房间主题、道具、光声配置
├─ AudioDirector：森林与房间声音的交叉淡入淡出
├─ DataPanelBridge：面板过渡、链接打开、返回恢复
└─ UI：标签、门牌、提示、操作与探索记录
```

第一版采用简单碰撞范围和明确路径，不引入完整物理系统。交互优先使用“接近后按键／点击”以兼容键鼠；蘑菇和草丛主要承担视觉作用，不做逐个可交互对象。

### 状态流

```text
森林探索 → 门口聚焦 → 敲门 → 预设许可 → 茧丝开门 → 室内探索
                                                    ↓
返回森林 ← 离开房间 ← 返回室内 ← 网页数据界面 ← 面板视角切换
```

第一版的示例茧房由内容预设许可状态；无需假装有实时玩家在线。关门茧房显示不可进入的原因。第二版才改为由屋主设置开关门、接收申请并决定许可。

## 3. 数据页面接入契约

第一版为每间茧房保留 `dataUrl` 配置。在真实地址提供前，使用项目内的示例数据页验证完整流程；示例内容须标明为演示数据。

```ts
type CocoonConfig = {
  id: string;
  title: string;
  publicTags: string[];
  themeId: string;
  entrance: 'open' | 'closed';
  demoAccess: 'granted' | 'denied';
  dataUrl?: string;
};
```

点击信息面板时，先暂停角色移动并播放第三人称到面板正面的镜头过渡，再打开数据页面。优先考虑同站点的应用内页面；若后续地址属于其他站点，则在新标签页打开并保持游戏页与位置。只有确认目标页面允许嵌入时，才使用页内 iframe；目标站点可通过 `frame-ancestors` 等策略限制嵌入，见 [MDN 文档](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors)。返回游戏时恢复室内镜头与操作。

第二版如包含真实用户数据，进入许可与数据页面访问必须由服务端共同验证；游戏内的开门动画本身不能作为访问控制。

## 4. 针毡美术的网页实现原则

1. **先做造型，再做质感**：圆润的不规则轮廓、可见的绒团和手工接缝，比大量细丝更能在中远景被看见。
2. **近景必须有真实绒毛层次**：刺猬的腹部短绒、背刺和脸部边缘不能只用噪声贴图代替。密集细绒与成组背刺以实例化几何、毛束卡片或同等方案制作；颜色、粗糙度与法线纹理辅助表现纤维，远景再使用简化层级控制开销。身体与背刺要在同一轮廓上连续生长。
3. **道具做可复用组件**：针毡蘑菇至少有单只、成簇、高矮三种组合；通过尺寸、转角和位置变化丰富森林。
4. **房间有统一模板和可替换主题**：共用树洞入口、完整茧丝穹顶与基本碰撞空间，中央保留柔光数据面板和可走通道；替换道具组、蓝橙红局部光、环境声和面板视觉。参考图中的外部剖面仅用来判断材质，不作为室内镜头。
5. **把细节集中在近景**：重点打磨刺猬、蘑菇、门口和一间代表性茧房；远处森林使用简化模型、雾和背景层次。

用户提供的图片是美术参考，不是可直接放进场景的 3D 模型。第一版目标是抓住圆润轮廓、纤维质感和微缩摄影的光线层次，不以逐像素复现图片为验收标准。网页端先按桌面键鼠体验设计；触屏操作待目标设备明确后安排。需要在目标演示设备上测量加载、帧率和内存，再决定模型与贴图预算；不要仅凭单张效果图估算网页端性能。

## 5. 阶段执行步骤

下表按当前工作区的《24 小时黑客松》流程编排。若项目不受 24 小时限制，保留阶段顺序，放宽制作时间即可。

| 阶段 | 参考时间 | 执行步骤 | 交付与验收 |
|---|---:|---|---|
| 0. 定范围 | T+0～2h | 确定一条演示路线、3 间示例茧房的内容主题；选定一间重点打磨；列出装扮与操作方式；确认刺猬与蘑菇模型由谁制作 | 一页场景清单、交互流程、需制作的资源清单 |
| 1. 灰盒闭环 | T+2～5h | 建 Vite/Three.js 项目；用基础几何体做森林、刺猬占位、树洞与室内；完成移动、碰撞、门口交互和场景切换 | 无美术资源也能从自己房间走到另一间房并返回 |
| 2. 核心表现 | T+5～10h | 替换刺猬、树洞、蘑菇资源；完成第三人称镜头、门口特写、茧丝开门和面板视角切换 | 演示主路径连续可玩，镜头与人物无明显穿模 |
| 3. 内容接入 | T+10～14h | 用配置生成 3 间不同主题房间；配置色光和环境声；接入演示数据页、探索记录和基础 UI | 三间房可辨认；面板能打开页面并返回原位置 |
| 4. 验收收缩 | T+14～18h | 在实际演示浏览器检查加载、键鼠操作、音频、返回、低帧率和错误链接；优先修复主路径 | 完整走通两次演示；出现资源或链接失败时可继续游戏 |
| 5. 路演准备 | T+18～24h | 固定演示设备和路线，准备备用录屏与讲解脚本，冻结代码 | 现场可重复演示“醒来→探索→敲门→入内→切换视角→看数据→返回” |

**时间不足时的降级顺序**：先减少森林范围和装饰密度，再把 3 间房缩为 1 间精致房＋2 间简化房；最后减少装扮选项。保留刺猬、3D 行走、开门动画、房间主题差异和面板视角切换这条核心闭环。

## 6. 第一版完成标准

- 刺猬可在森林与室内流畅移动，镜头跟随稳定，门牌文字可读。
- 开场能选择基础装扮与公开标签，并在自己的茧房看到选择结果。
- 玩家能从自己的茧房出发，拜访至少一间获准进入的茧房并返回；未经许可不能进入。
- 至少一间茧房完整体现“内容决定空间、颜色、声音”的设计，其他示例房能明显区分。
- 数据面板点击后先切换镜头，再打开示例网页；返回后不丢失游戏位置。
- 在目标演示设备上完成实际测量与两次连续演示，不发生阻断主路径的加载或交互错误。

## 7. 第二版扩展

在第一版闭环稳定后加入账号与角色档案、真实玩家茧房、开关门、访问申请与留言、屋主授权、消息通知、服务端权限校验，以及更多森林区域。此阶段需要后端存储、身份认证和权限接口；不应把第一版的本地预设许可直接当成真实授权机制。
