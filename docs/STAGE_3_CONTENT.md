# 《破茧》阶段 3 内容与数据页验收

状态：**用户已确认通过，可进入阶段 4**。入口：[`../reviews/stage-3.html`](../reviews/stage-3.html)。保持工程目录完整，直接打开 HTML 即可。阶段 2 的刺猬、森林、茧房外壳与茧内视角沿用已通过的版本。后续界面与面板调整见 [`STAGE_4_QA.md`](STAGE_4_QA.md)。

## 本阶段新增

| 示例茧房 | 室内布置 | 色光 | 声音 |
|---|---|---|---|
| 北侧树洞 · 自然观察 | 叶片、标本牌、苔藓观察台 | 苔绿 | 风与短促鸟鸣 |
| 溪畔倒木 · 远行见闻 | 毛毡地图、旅行箱、指南针 | 琥珀 | 稀疏风铃音 |
| 苔坡树桩 · 音乐收藏 | 悬挂圆片、琴键与唱片形物件 | 淡紫蓝 | 柔和的音符序列 |

内容主题只是**演示占位**。正式人物标签、内容标签与数据页面地址仍等待提供。数据字段集中在 [`../public/data/cocoons.js`](../public/data/cocoons.js)：`personTags`、`contentTags` 目前为空数组；每间房的 `dataUrl` 指向项目内的 `demo-data.html?room=...`。正式地址到位后，可按房间替换 `dataUrl`，无需修改 3D 场景逻辑。

室内中央面板仍使用示意的“用户画像／推荐路径／信息流”结构。靠近按 **E** 后镜头切到面板正面，点击“打开示例数据页”会在新标签打开[`示例数据页`](../reviews/demo-data.html)。切回原游戏标签，角色位置和房间保持不变；按 **Esc** 从面板近景继续探索。若将来提供的跨站页面不允许嵌入，仍可使用这个新标签方案。

探索过的三间房会记录在浏览器本机的 `localStorage`，右侧显示数量。重置当前位置会保留记录；“清空本机探索记录”可删除记录。若浏览器禁止 `file://` 页面使用本机存储，当前会话仍可计数，但关闭页面后可能不会保留。

声音由浏览器 Web Audio 合成，不依赖音频下载。需要点击“声音：关闭”主动开启；此后森林、自然观察、远行见闻和音乐收藏使用不同的低音量氛围。右侧“关闭／开放苔坡树桩”仅用于演示第一版的本地预设许可，关闭时不能进入。没有真实玩家审批或共享权限。

## 建议验收路线

1. 打开阶段 3 HTML，点击“声音：关闭”开启声音，从自己的茧房走进森林。
2. 分别走访左侧、中央、右侧三间茧房。比较布置、色光、声音与门牌主题。
3. 在其中一间房靠近中央面板，按 **E**，再点“打开示例数据页”。确认新标签页标注“仅供演示”，切回游戏后仍在原茧房。
4. 按 **Esc** 退出面板近景，走向室内出口返回森林。右侧“已探索”应随访问累加到 **3 / 3**。
5. 可先关闭苔坡树桩并尝试敲门，确认不能进入；再开放它，确认能进入。重置和清空记录按钮分别验收。

## 边界与下阶段

本阶段完成的是示例内容、氛围声和数据页跳转。数据页没有真实用户资料，音效是代码合成的方向稿；装饰物尚未做逐件碰撞。用户已同意继续阶段 4，对加载、帧率、移动碰撞、音频、错误链接和失败恢复作集中检查。

本地自动检查：`npm run test:stage3` 覆盖三间房、三种声音、数据链接、开关门、探索记录与重置；`npm run test:stage2` 用于确认上一阶段主路线未回归。
